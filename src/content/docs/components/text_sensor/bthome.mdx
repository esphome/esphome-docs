The `bthome` text sensor platform lets you receive string values broadcast by [BTHome v2](https://bthome.io/) Bluetooth Low Energy devices. The ESP32 acts as a passive BLE listener — it does not connect to the remote device, it simply receives its advertisements.

> [!WARNING]
> The BLE software stack on the ESP32 consumes a significant amount of RAM on the device.
>
> **Crashes are likely to occur** if you include too many additional components in your device's
> configuration. Memory-intensive components such as [Voice Assistant](/components/voice_assistant/) and other
> audio components are most likely to cause issues.

> [!NOTE]
> This platform requires the [BTHome](/components/bthome/) component to be configured with at least one `remote_devices` entry.

```yaml
# Example configuration entry
esp32_ble_tracker:

bthome:
  remote_devices:
    - mac_address: "AA:BB:CC:DD:EE:FF"
      id: my_sensor_device

text_sensor:
  - platform: bthome
    source_id: my_sensor_device
    type: text
    name: "Device Status"
```

## Configuration variables

- **source_id** (**Required**, [ID](/guides/configuration-types#id)): The ID of the remote device declared in the `bthome` component's `remote_devices` list.
- **type** (**Required**, string): The BTHome text sensor type to receive, `text` or `raw`. Must be one of the [supported text sensor types](/components/bthome#supported-text-sensor-types). Type names are case-insensitive.
- **on_raw_data** (*Optional*, [Automation](/automations)): An automation to run when a `raw` object is
  received. Only available with `type: raw`. See [`on_raw_data`](#on_raw_data).
- All other options from [Text Sensor](/components/text_sensor).

A `text` object must be valid UTF-8. If it is not, the update is ignored and a warning is logged, because Home
Assistant cannot receive text that is not valid UTF-8.

## Raw data

A `raw` object carries binary data. A text sensor state must be text, so the bytes are published as lowercase
hex: the bytes `DE AD BE EF` become the state `deadbeef`.

### `on_raw_data`

This automation runs with the original bytes of each received `raw` object, before they are converted to hex.
In lambdas, the bytes are available as `x`, a `std::span<const uint8_t>`. The bytes are only valid while the
automation runs, so copy any value you want to keep.

```yaml
text_sensor:
  - platform: bthome
    source_id: my_sensor_device
    type: raw
    name: "Device Raw Data"
    on_raw_data:
      - lambda: |-
          if (x.size() >= 2) {
            // Decode a little-endian 16-bit value from the first two bytes
            uint16_t value = x[0] | (x[1] << 8);
            id(decoded_value).publish_state(value);
          }

sensor:
  - platform: template
    id: decoded_value
    name: "Decoded Value"
```

## Encrypted devices

To receive data from a device that uses BTHome encryption, add a `key` to the remote device entry:

```yaml
bthome:
  remote_devices:
    - mac_address: "AA:BB:CC:DD:EE:FF"
      id: my_sensor_device
      key: "0123456789ABCDEF0123456789ABCDEF"

text_sensor:
  - platform: bthome
    source_id: my_sensor_device
    type: text
    name: "Device Status"
```
