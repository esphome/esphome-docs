---
title: "1-Wire Device Emulation"
description: "Experimental DS18B20-compatible 1-Wire device emulation on an externally powered ESP32."
---

The `one_wire_device` component lets an ESP32 respond to an external 1-Wire controller as one
DS18B20-family temperature device. It returns a configured fixed temperature; it does not measure temperature.
It requires an [ESP32](/components/esp32/) and is separate from the [1-Wire controller bus](/components/one_wire/).

:::caution[Experimental]
This component is not production-qualified. Initial wired reads succeeded, but subsequent diagnostic stress
experiments encountered CRC, presence and timing failures. Reliable operation under background load remains
unresolved. Do not use this prototype for heating protection, safety interlocks or other critical measurements.
:::

```yaml
one_wire_device:
  pin: GPIOXX
```

## Wiring

Connect the configured data pin to the external controller's DQ line and connect their grounds.
Fit an external 4.7 kOhm pull-up resistor between DQ and 3.3 V. The ESP32 configures its DQ pin as open-drain:
it pulls the line low or releases it, rather than actively driving a high level.

Power the ESP32 independently. Do not connect independently powered boards' 5 V rails together.
Parasite power and 5 V data-line operation are not supported. Use a plain, non-inverted, output-capable GPIO;
advanced pin options are not all honored by the backend's raw GPIO configuration.

## Configuration Variables

- **pin** (**Required**, [Pin Schema](/guides/configuration-types/#pin-schema)):
  The internal GPIO used for the shared DQ line. An external pull-up is required.
- **address** (*Optional*, hexadecimal integer): The 64-bit ROM address in ESPHome's little-endian numeric
  representation. A nonzero address must have family byte `0x28` and a valid Dallas CRC. Defaults to `0`,
  which derives a stable ROM from the ESP32 station MAC address and calculates its CRC. The ROM is logged at startup.
- **temperature** (*Optional*, float): The fixed temperature returned by the emulated device, in degrees Celsius.
  Defaults to `23.5`. Accepted range is `-55.0` to `125.0`. No sensor-source or template input is available.
- **interrupt_mode** (*Optional*, boolean): Selects the GPIO edge-interrupt backend when `true` (the default).
  When `false`, selects the older high-priority timing-task backend. That backend pins its task to core 1;
  it is not supported on single-core ESP32 variants.
- **timing_scale** (*Optional*, integer): Bench diagnostic multiplier from `1` to `100`. Defaults to `1`,
  which uses normal-speed timings. Larger values require a correspondingly modified controller and are
  **not** standard-speed 1-Wire operation. Leave this at its default for ordinary interoperability testing.
- **id** (*Optional*, [ID](/guides/configuration-types/#id)): Identifier for the component instance.

## Controller Configuration

A separate ESPHome controller can use the existing GPIO [1-Wire bus](/components/one_wire/gpio/) and
[Dallas temperature sensor](/components/sensor/dallas_temp/). Configure those components on the controller,
not on the emulating ESP32's same data pin. Obtain the emulated ROM from the device startup log or the
controller's bus scan, then select that address when other devices share the bus.

At `timing_scale: 1`, no diagnostic timing modification is required on the controller. The accompanying
GPIO-controller `timing_scale` option is only for matched, deliberately slowed bench experiments; leave it
at its default of `1` for an ordinary controller.

## Supported Scope and Limitations

Hardware development used classic dual-core ESP32-D0WD-V3 revision 3.1 modules. Other ESP32 variants have
not been qualified. Arduino and ESP-IDF compile fixtures do not establish physical protocol reliability.

The implementation includes ROM Search, Read, Match and Skip paths, plus DS18B20-like Convert T,
Read/Write Scratchpad and Read Power Supply paths. It is not a complete DS18B20 emulator:

- Conversion completion polling/timing and resolution handling are incomplete.
- Copy Scratchpad does not persist settings; recall and alarm search are not implemented.
- Only one virtual device with a fixed temperature is provided.
- Dynamic sensor sources, overdrive and parasite power are not supported.
- The interrupt backend busy-waits through timing-critical operations. Coexistence with other components,
  network traffic and long-running workloads must not be assumed to be reliable.

An earlier bring-up report recorded 64 valid reads without CRC/reset/slot errors in that run. Later two-hour
fixed-scratchpad diagnostic experiments failed for both tested GPIO and GPTimer variants. Those experimental
images are not a qualification of the current source, and the GPTimer backend is not included here.
