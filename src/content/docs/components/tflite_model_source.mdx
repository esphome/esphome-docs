---
description: "Model source resolution and metadata parsing library for TFLite Micro components"
title: "TFLite Model Source"
---

The `tflite_model_source` component is a **library-only component**: it has no user-facing configuration options and is
loaded automatically as a dependency of the `tflite_micro_runtime`
component and of the third-party components that consume it.

It accepts model sources in three forms and downloads them into the ESPHome external-files cache at
configuration time:

| Type | Syntax | Description |
|---|---|---|
| Local file | `"path/to/model.tflite"` | Path relative to the configuration directory. |
| GitHub shorthand | `"github://user/repo/path/model.tflite"` | Reads the model file from a repository. |
| HTTP(S) URL | `"https://example.com/model.tflite"` | Downloads the file, or a JSON manifest naming it. |

The same package also parses the companion `.txt` metadata reports (autodetected input shape, arena size,
operator count and output processing) and the filename heuristics (`_GRAY`, `_RGB`, `_BGR`, `_10cls`) used
when no report is available.

## Example configuration entry

The component has no options of its own; configuring it explicitly only loads the library:

```yaml
tflite_model_source:
```

It is normally loaded by `tflite_micro_runtime`:

```yaml
tflite_micro_runtime:
  - id: digit_reader
    model_type: image
    model: "models/digit_recognizer.tflite"
```
