The PCA9554 component allows you to use a variety of I/O expanders in ESPHome that use the [I²C Bus](/components/i2c) 
for communication. Once configured, you can use any of the IO pins (up to 16) with your projects. Within ESPHome they 
emulate a real internal GPIO pin and can therefore be used with many of ESPHome's components such as the GPIO
binary sensor or GPIO switch. Any option accepting a [Pin Schema](/guides/configuration-types#pin-schema) can theoretically
be used, but some more complicated components that do communication through this I/O expander will not work.

## Supported devices

Set `device:` to the part in use. The PCAL parts add pull resistors, input latching and a selectable output
drive strength on top of the plain I/O.

| Device | Number of Pins | I²C Address | Features |
| --- | --- | --- | --- |
| PCA9554 | 8 | 0x20-0x27 | I/O |
| PCA9554A | 8 | 0x38-0x3F | I/O |
| PCA9536 | 4 | 0x41 | I/O |
| PCA9535 | 16 | 0x20-0x27 | I/O |
| PCA9555 | 16 | 0x20-0x27 | I/O |
| PCAL9538 | 8 | 0x70-0x73 | I/O, pull up/down, latching, drive strength |
| PCAL9555 | 16 | 0x20-0x27 | I/O, pull up/down, latching, drive strength |

Devices that show a range of I²C addresses have an address that can be set using strapping pins on the device.

Other I/O expanders with the same register layout and up to 16 pins, such as the TCA9554 and TCA9535, work when
configured as the device with the same number of pins and features; only the I²C address range differs.

```yaml
# Example configuration entry
pca9554:
  - id: "setup_expander"
    address: 0x70
    device: PCAL9538

# Individual outputs
switch:
  - platform: gpio
    name: "PCAL9538 Pin 2"
    pin:
      pca9554: setup_expander
      number: 2
      drive_strength: 2
      mode:
        output: true

binary_sensor:
  - platform: gpio
    name: "PCAL9538 Pin 3"
    pin:
      pca9554: setup_expander
      number: 3
      mode:
        input: true
        pullup: true
        latch: true
```

## Configuration variables

- **id** (**Required**, [ID](/guides/configuration-types#id)): The id to use for this `pca9554` component.
- **address** (*Optional*, int): The I²C address of the driver. This is technically optional, but you should
  really check to make sure you have the right address as the default will not work for many of the supported
  components. Defaults to `0x20`.

- **device** (*Optional*, string): The part in use, one of the names in the table above. Defaults to `PCA9554`,
  or to the plain part with the pins given by `pin_count`.
- **pin_count** (*Optional*, int): The number of pins of the expander, `4`, `8` or `16`, for configurations that
  predate `device`. With `device` set it may be left out; if both are given they must agree.
- **interrupt_pin** (*Optional*, [Pin Schema](/guides/configuration-types#pin-schema)): The pin connected to the
  INT output of the expander. When configured, the component becomes interrupt-driven instead of
  polling: it only reads the chip when a pin actually changes state, significantly reducing I²C bus traffic
  and CPU usage. The INT pin is active-low and open-drain, so an external or internal pull-up resistor is
  required. Must be an internal GPIO pin (not another expander pin). On the PCAL parts every input pin asserts
  INT and every output pin is masked, so no per-pin setup is needed.

## Pin configuration variables

- **pca9554** (**Required**, [ID](/guides/configuration-types#id)): The id of the `pca9554` component of the pin.
  Instead of an id, an `address:` can be given to select the hub by its I²C address; see
  [Selecting an I2C Expander by Address](/guides/configuration-types#selecting-an-i2c-expander-by-address).
- **number** (**Required**, int): The pin number.
- **inverted** (*Optional*, boolean): If all read and written values
  should be treated as inverted. Defaults to `false`.
- **drive_strength** (*Optional*, int): PCAL parts only. The drive strength of an `output` pin, `0` for a
  quarter, `1` for half, `2` for three quarters and `3` for the full strength. Refer to the datasheet of your
  device for the recommended value. Defaults to full strength; the plain parts reject this option.
- **mode** (*Optional*, boolean(s)): Pin mode settings for the selected pin. Multiple pin modes may be selected by
  indenting them after the `mode:` entry in the YAML as shown in the example above. All devices support `input` and
  `output`. The PCAL parts additionally support `pullup`, `pulldown` and `latch`; the plain parts reject them.

> [!NOTE]
> Pin numbers always start at 0. For devices with more than 8 pins, the datasheet may call them out in two ports (ex: P0_0..7 and P1_0..7). In this case, the port 0 pins are the lower eight pins of the expander, and the port 1 pins are the upper eight (ex: P0_4 is pin four, P1_4 is pin 12)

## Description of the mode settings

`input`:
Define the device as a high impedance input.

`output`:
Define the device as a push/pull output

`pullup`:
If the pin is configured as an `input` enable a 100K pull up.

`pulldown`:
If the pin is configured as an `input` enable a 100K pull down.

`latch`:
If the pin is configured as an `input`, latch the input. With this enabled, if the input changes state, the pin
state will be latched at the new level, and will not change, even if the pin goes back to its original state.
This latch is cleared when the pin state register is read. This is likely only useful if you are trying to
detect *very* fast transient signals.
